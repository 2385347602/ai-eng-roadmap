00 · 定位与认知 ​

投入权重：5% · 这一层不产出代码，但决定你后面半年会不会走错方向。 很多转岗的人直接跳到 LangChain，结果学成了调包工。

这一层要解决的问题 ​

转岗最大的风险不是"学不会"，是"学错方向"。AI 应用这个领域的信息密度极低、噪声极高——大量内容是模型厂商的营销、框架作者的布道、以及三个月就过期的教程。这一层的作用是先建立判断力，让你能分辨"什么是长期有效的能力"和"什么是今年流行明年就废的工具"。

角色与边界 ​

  • AI 应用工程化的定义 必须 — 把概率性的模型能力封装成稳定、可交付、可运维的产品。边界止于"不训练基座模型"，往上包含产品形态设计。
  • 三层分工：模型层 / 推理层 / 应用层 必须 — 模型层做预训练与对齐（博士 + 千卡），推理层做部署与加速（系统工程师），应用层做产品（你）。转岗默认进第三层。
  • 与算法工程师的区别 必须 — 算法关心"模型能力上限"，应用关心"在成本与延迟约束下，把能力转化成可用的任务完成率"。
  • 与数据工程师的区别 重要 — 数据工程做管道与数仓，AI 应用做检索、编排、评测。两者在 RAG 的数据接入处重叠。
  • 岗位画像：AI 应用工程师 / LLM 工程师 重要 — 前者偏产品与全栈，后者偏 pipeline 与模型适配。国内 JD 常混用，看职责里"是否要求发论文"来区分。
  • 岗位画像：Agent 工程师 / AI 产品工程师 选学 — Agent 工程师重点在工具设计与可靠性；AI 产品工程师重点在场景选型与人机边界。

心智模型 ​

  • 交付物思维 > 技术栈思维 必须 — 判断标准不是"我会几个框架"，而是"我交付过几个有评测、有监控、有人用的系统"。
  • demo 与产品的分水岭是评测 + 可观测 必须 — 能跑通叫 demo，能回答"这次改动是变好还是变坏"才叫产品。九成人卡在这条线。
  • 概率性系统的心智模型 必须 — 传统工程是确定性的：同样输入必得同样输出。LLM 是分布采样，你必须习惯"用统计指标代替断言"。
  • 单步可靠性的连乘衰减 必须 — 单步 95% 正确，10 步串联只剩约 60%。这是 Agent 一切工程约束的源头，也是"为什么优先用工作流"的答案。
  • 能力边界意识 重要 — 清楚模型在哪类任务上不可靠（精确算术、实时事实、长链推理、空间关系），才不会设计出必败的产品。
  • 成本即产品约束 重要 — token 成本直接决定定价、上下文长度、能否多轮。不懂成本核算的设计都是纸上谈兵。
  • 信息半衰期 重要 — 框架 API 半年一变，原理三五年不变。学不动的时候，回到原理。

你的起点（前端） ​

  • 存量优势：流式 UI 与交互设计 必须 — 大量 AI 产品是后端工程师写的，交互烂到没法用。能把不确定输出做成可用界面的人极度稀缺，这是你真正的护城河。
  • 存量优势：状态管理与性能优化 必须 — 多轮会话状态、长列表虚拟滚动、增量渲染——这些在 AI 场景是硬需求，恰好是前端老本行。
  • 缺口一：Python 生态 必须 — 不是学语法，是熟悉数据处理（pandas）、异步（asyncio）、以及 AI 库的调用习惯。目标：能读懂并改开源实现。
  • 缺口二：数据处理与清洗 必须 — RAG 八成时间花在文档解析和清洗上，这部分最脏最没技术光环，也最能拉开差距。
  • 缺口三：评测思维 必须 — 前端习惯"我看一眼没问题"，AI 必须"用 200 条样本证明没退化"。这是最难改的习惯。
  • 缺口四：服务端与运维常识 重要 — 容器、队列、限流、日志、成本分摊。前端容易只关注浏览器侧。
  • 缺口五：概率与统计直觉 重要 — 分位数、置信区间、显著性。看懂 P95 延迟和 A/B 结果需要它。

常见误判（提前避坑） ​

  • 误判一：以为要学完数学 — 转应用层不需要重学线代和微积分。需要的是"能解释现象"，不是"能推导梯度"。
  • 误判二：以为框架最重要 — LangChain 的抽象在生产环境经常是负担。会裸调 SDK 比会框架值钱。
  • 误判三：以为 prompt 是玄学 — 它有工程方法（结构化、评测驱动、版本管理），但确实没有"咒语"。
  • 误判四：以为 Agent 是终局 — 生产环境里大量"Agent"实际是带 AI 节点的固定工作流，因为可预测、可测、便宜。
  • 误判五：先学微调 — 这是投入产出比最低的起点。先把 RAG 和评测跑通，再谈微调。
