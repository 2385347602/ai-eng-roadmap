14 · 岗位画像与能力矩阵 ​

这一章回答一个问题：招聘方到底在找什么样的人，以及你现在的差距具体在哪。

一、先把岗位分清楚 ​

"AI 应用工程师"不是一个标准化职位，市面上至少有三类，要求差别很大。投错方向，你会觉得"我明明会为什么不要我"。

类型 A：AI 应用工程师 / LLM 应用开发 ​

做什么：把一个业务场景做成可用的 AI 产品。从需求、数据、检索、编排、前端到上线，全链路都碰。

典型要求：

  • 熟练 Python 或 TypeScript，能独立写服务
  • 有 RAG 落地经验（注意是"落地"，不是"了解"）
  • 会用主流模型 API，理解 prompt 工程
  • 能设计评测方案
  • 有完整项目从 0 到 1 的经历

面试重点：项目细节、指标、踩过的坑。技术深度其次，**"你真的做过吗"**是第一位。

匹配度：★★★★★ 前端转岗最现实的入口。

类型 B：LLM 工程师 / 算法应用工程师 ​

做什么：偏模型侧。微调、蒸馏、评测体系、推理优化。

典型要求：

  • 熟悉 Transformer、SFT、LoRA、DPO
  • 有微调实战（数据构造、超参、效果评估）
  • 懂推理框架（vLLM / SGLang）
  • 通常要求硕士或论文

面试重点：原理深度、训练细节、指标对比。

匹配度：★★☆☆☆ 需要补的太多，不建议作为第一目标。但可以作为第二年方向。

类型 C：AI 产品工程师 / AI 全栈 ​

做什么：小团队里一个人扛整个产品。前端 + 后端 + AI 全包。

典型要求：

  • 前端熟练（React / Vue）
  • 能写后端 API
  • 懂 AI 能力边界，能把控产品形态
  • 通常出现在创业公司或大厂创新业务

面试重点：全栈能力、产品判断、上手速度。

匹配度：★★★★★ 你的前端背景在这里是加分而不是减分。

建议路径：先进 A 或 C，做满一年有真实项目后再考虑 B。

二、JD 里那些话翻译过来是什么 ​

招聘描述有一套自己的黑话。看懂这些，你就知道该准备什么。

JD 原文真实含义你该怎么准备
熟悉 RAG 技术栈至少做过一个能上线的知识库准备一个带指标的项目，能讲清分块和重排
有 LLM 应用落地经验你踩过坑，不是只跑过 demo准备 2~3 个真实故障的排查过程
熟悉 Prompt Engineering会写结构化 prompt，不是会念咒能讲 prompt 版本管理和 A/B 评测
具备工程化能力你写的东西别人能维护讲清你的架构分层、日志、配置管理
了解 Agent知道它能做什么、不能做什么讲清你为什么在某场景没用自主 Agent
有较强的学习能力这行变得快，别只会一个框架讲你最近三个月学了什么、怎么学的
熟悉向量数据库用过，知道怎么选能对比 pgvector 和 Milvus 的取舍
有 ToB 项目经验你处理过权限、私有化、合规准备权限隔离和私有部署的细节

一个关键判断：JD 里写"了解"的，面试最多问一层；写"熟悉/精通"的，会追问到底层。别把精力平均分配。

三、能力矩阵（自评用） ​

十二项能力，四级。这个分级是我的判断，不是行业标准，但拿来定位差距够用。

能力项L1 知道L2 做过L3 做好过L4 能教人
1. 模型调用与参数会调 API懂 temperature 影响能按场景定参数并解释能建立团队规范
2. Prompt 工程会写 prompt会结构化 + few-shot有版本管理和评测驱动能设计 prompt 体系
3. 上下文管理知道窗口限制会做历史裁剪会动态组装 + 压缩能设计上下文架构
4. 文档解析与清洗会用 loader处理过 PDF 难点建过解析流水线能评估解析质量并优化
5. 检索（含混合+重排）会向量检索会混合检索有 Recall 指标优化经验能设计检索架构
6. 评测体系知道要评测建过评测集有 LLM-judge 校准经验能建评测流程并进 CI
7. Agent 与工具会 function calling写过 ReAct有可靠性设计（终止/幂等/审批）能设计多 Agent 架构
8. 后端工程会写接口会异步 + 队列懂限流熔断降级能设计高可用架构
9. 前端交互会写页面会流式渲染解决过性能与抖动问题能定义交互范式
10. 可观测与成本会打日志接入了 trace有成本优化案例能建成本模型
11. 安全与合规知道有风险做过输入输出校验处理过权限隔离能过合规评审
12. 部署与运维会部署会容器化做过容量规划能定 SLA

怎么用这张表 ​

上岗门槛：第 1~7 项至少 L2，其中 5（检索）和 6（评测）要到 L3。

为什么是这两项：面试官判断"你是不是真做过"，最常用的两个探针就是"你的召回率多少、怎么测的"和"你怎么知道改完变好了"。这两题答不上来，其他说得再好也会被归为"只跑过 demo"。

你的现状（按前端背景推断，你可以自己修正）：

  • 第 9 项大概已经是 L3~L4，这是你的存量
  • 第 8 项大概 L2，补异步和队列就够
  • 第 4、5、6 项是 0，这是必须补的
  • 第 7 项是 0，但补起来快

四、简历怎么写 ​

技术能力相同的情况下，简历决定你有没有面试机会。三条规则：

规则一：每个项目必须有数字 ​

对比一下：

❌ 使用 LangChain 和向量数据库搭建了企业知识库问答系统，支持文档上传和智能问答。

✅ 独立搭建企业知识库问答系统，处理 1.2 万份 PDF（含 30% 扫描件），自建解析流水线解决双栏与跨页表格问题；混合检索 + bge-reranker 重排，200 条评测集上 Recall@5 从 62% 提升到 89%；通过父子块与上下文压缩把单次成本降低 40%。

第二段没有用任何高级词，但它证明了四件事：你处理过脏数据、你知道怎么量化、你做过优化、你有成本意识。

规则二：写"我解决了什么"，不写"我用了什么" ​

技术栈是门槛，不是亮点。面试官默认你会用工具，他想知道的是你解决了什么别人解决不了的问题。

规则三：准备三个"深挖点" ​

简历上每个项目，你都要预判面试官会往哪里挖，并且准备好三层深度的回答：

  • 第一层：做了什么（30 秒）
  • 第二层：怎么做的，为什么这么选（2 分钟）
  • 第三层：遇到过什么坑，怎么定位的，如果重做会怎么改（5 分钟）

第三层是分水岭。 能讲清"如果重做会怎么改"的人，说明他真的复盘过；讲不出来的人，多半是跟着教程做的。

五、面试流程与各轮重点 ​

典型流程四到五轮，每轮考察的东西完全不同，准备策略也不同。

第一轮：技术初筛（30~45 分钟） ​

通常问基础概念 + 项目概览。

重点：能不能把项目讲清楚。这轮淘汰的是"简历写得比实际好"的人。

准备：把项目讲成 3 分钟版本，包含背景、你的角色、技术选型理由、结果数字。

第二轮：技术深挖（60 分钟） ​

往死里问项目细节，会追问到你答不上来为止。

重点：真实性和深度。

典型追问链：

"你说用了混合检索" → "权重怎么定的" → "为什么是这个比例" → "调之前是多少" → "你怎么知道调完更好了" → "评测集多少条" → "评测集怎么来的"

这条链能一路问到底的人，一定是真做过。

第三轮：系统设计（45~60 分钟） ​

给一个场景，让你设计系统。

重点：架构能力、边界意识、取舍。

典型题目：设计一个支持 10 万文档、500 并发、多租户隔离的企业知识库。

准备：背熟第 10 章的架构图，并且能讲清每个组件的必要性（"为什么需要模型网关"而不是"我们有个网关"）。

第四轮：编码（45~60 分钟） ​

写代码。通常不是算法题，是工程题。

典型题目：实现一个带重试和流式的模型调用封装；实现一个简单的 RAG 检索函数。

重点：代码质量、异常处理、边界情况。

第五轮：HR / 交叉面 ​

问动机、稳定性、薪资。

重点：你为什么转、能不能扛住不确定性。

准备：不要说"AI 是趋势所以我想转"。要说具体的东西：你做了什么、发现了什么问题、想解决什么。

六、一个残酷的判断 ​

面试能不能过，七成取决于你有没有一个真做过、有数字、能扛住三层追问的项目，三成才是知识点覆盖。

所以如果你的时间有限，优先级应该是：

  1. 做一个能扛住追问的项目（占 60% 时间）
  2. 把项目的每个技术选择都想清楚"为什么"（占 25% 时间）
  3. 补知识点盲区（占 15% 时间）

反过来做——先刷完所有知识点再动手——你会发现自己能背出 RAG 的定义，但答不上"你的分块大小是多少、为什么"。
