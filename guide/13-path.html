13 · 路径与项目 ​

知识清单不等于学习计划。这一层给顺序和验收标准——每个阶段都有"做出来什么"，而不是"学了什么"。

为什么要有验收标准 ​

"学完 RAG"这句话没有意义，因为永远学不完。有意义的是"我做出了一个 Recall@5 达到 80% 的知识库，并且能说清每个错误是检索问题还是生成问题"。

验收标准的作用是把"感觉学会了"变成"可以被别人检验"。 它同时也是你面试时唯一能讲的东西——面试官不关心你看了什么教程，只关心你做出来的东西有什么数字。

五个阶段 ​

阶段 0（2 周）：跑通与认知 ​

  • 读完本图第 00~02 层
  • 用官方 SDK 裸调三家厂商的 API（不要用框架）
  • 写一个流式聊天页面，支持中断与重新生成

验收：能解释 token 计费怎么算、temperature 调高会发生什么、为什么流式输出是单向的。

阶段 1（4~6 周）：RAG 端到端 ​

  • 做一个能上传文档、能溯源引用、有 50 条评测集的知识库
  • 至少实现混合检索 + 重排
  • 记录每次检索的完整 trace

验收：Recall@5 ≥ 80%，且拿到一个错误案例时，能判断是"没检索到"还是"检索到但没用"。

阶段 2（4 周）：Agent 与工具 ​

  • 写 3 个工具 + ReAct 循环 + 人工审批点 + 成本上限
  • 加终止条件（最大步数 / 最大成本 / 无进展检测）
  • 每一步都能回放

验收：10 步任务成功率 ≥ 70%，且有完整 trace 可回放；故意制造工具失败，系统能自愈或优雅退出。

阶段 3（3 周）：评测与可观测 ​

  • 接入 Langfuse（或同类）
  • 把评测跑进 CI，prompt 改动自动回归
  • 建立 badcase 归因流程

验收：一次 prompt 改动能给出"变好/变坏"的量化结论，而不是"我感觉好点了"。

阶段 4（按需）：微调与部署 ​

  • LoRA 微调一个小模型
  • vLLM 部署 + 量化对比
  • 算出"自部署 vs 调 API"的成本交叉点

验收：能给出一个有数字的结论："在我们的 QPS 下，自建在每月 X 次请求以上才划算"。

四个能写进简历的项目 ​

1. 带评测的企业知识库 ​

亮点不是"用了 RAG"，而是"有 200 条评测集、Recall 从 62% 提到 89%、成本降 40%"。数字是唯一有说服力的东西。

要能讲清三件事：为什么选这个分块策略（有对比实验）、为什么加重排（有前后指标）、权限隔离怎么做的（有越权测试）。

2. 多工具 Agent + 人工审批 ​

亮点是可靠性设计：终止条件、幂等、审批点、trace 回放。讲的时候重点放在"我怎么让它不出事"，而不是"它能做多少事"。

3. 模型网关 + 成本看板 ​

亮点是工程性：多模型路由、降级、限流、按租户成本分摊。这个项目最像真实生产系统，也最能体现你从"做功能"到"做平台"的跨越。

4. 给开源项目提 PR ​

LangChain / LlamaIndex / Langfuse 的 issue 区里挑真实 bug。这是最快的背书——它证明你能读懂别人的大型代码库。

时间分配建议 ​

如果你每周能投入 10 小时，大概是这样：

阶段周数累计
0 跑通22
1 RAG57
2 Agent411
3 评测与可观测314
4 微调与部署317

这是经验估算，不是承诺。 实际耗时高度取决于你每天能投入多少、以及第一个项目遇到的文档解析有多脏。做好"RAG 阶段超时"的心理准备——这是最常见的。

资源 ​

  • 必读文档 必须 — OpenAI / Anthropic / Qwen 的官方 prompting 与 tool use 文档，比任何二手教程准。
  • 必读文章 必须 — Anthropic《Building Effective Agents》——关于"为什么优先用工作流"的最佳论述。
  • MCP 规范 必须 — modelcontextprotocol.io 的规范与示例，一小时能读完。
  • 开源项目精读 重要 — 选一个 RAG 框架读它的检索链路源码，比看十篇博客有用。
  • 论文 重要 — 只挑必要的：Attention Is All You Need、RAG 原论文、LoRA、DPO、ReAct。
  • 社区 选学 — LangChain / LlamaIndex Discord、HuggingFace 论坛、以及国内的 AI 工程实践群。

最后一句 ​

这份清单有 400 多条，别指望按顺序全做完。正确用法是：先按阶段走主干，遇到具体问题再回来查。

真正决定你能不能转成的，不是覆盖了多少条，而是你有没有一个"能拿出数字"的项目。清单是地图，项目是路。
