LLM 基础：你调的到底是个什么东西

它是一个"总要说下一个词"的概率机器。理解这句话，九成的踩坑都能提前避开。

第 1 / 8 步

一句话说清模型在做什么

大语言模型做的事，字面上只有一件：给定前面的文本，算出下一个 token 的概率分布，挑一个，接上去，重复。

你看到的"理解""推理""写代码"，是这件事在极大规模上涌现出来的效果。这个认知很重要，因为它直接解释了三件事：为什么模型会编造、为什么同一个问题两次答案不同、为什么它算不准大数乘法。

前端经验类比
和 Vue 的响应式类比

Vue 的响应式本质是"读时收集依赖，写时触发更新"——一句简单规则，组合出整个框架的能力。LLM 也一样：一句"预测下一个 token"，组合出写作、翻译、写代码、多步推理。理解底层规则，你才知道边界在哪。

三个直接推论

  1. 它没有数据库。 它不知道你的笔记内容、今天的股价、你公司的制度。除非你在 prompt 里给它，或者给它一个工具去查。
  2. 它不"计算"，它"续写"。 它见过 "1+1=" 后面跟 "2"，所以能答对；但 17 位数的乘法它没见过，只能猜。所以数值计算必须交给代码。
  3. 它没有"我不知道"这个默认选项。 训练目标是"给出最可能的续写"，而"我不知道"在语料里很少跟在问题后面。所以它倾向于编一个像样的答案——这就是幻觉的结构性来源。
★这一课最实用的一句

凡是要求"确定性"的地方，都不要指望模型。 金额计算、权限判断、状态流转、格式校验——这些必须由代码做。模型只负责"生成候选"和"理解模糊输入"。

项目一 · 知识库问答系统的后端骨架

这一课给你判断"哪里该用模型、哪里该用代码"的依据，以及成本/延迟的量级感。项目里所有 LLM 调用点都要在这里定下参数和预算。

这一课要做的
  1. 给项目加一个 llm/client.ts，封装调用、记录 usage、统一超时与重试
  2. 为三类任务分别配置参数（抽取 0、改写 0.9、代码 0.2），写进配置而不是散在代码里
  3. 实现 token 估算与成本统计，按天聚合到一张 model_usage 表
  4. 把"金额计算""权限判断"这类逻辑显式标注为"不用模型"，写进架构文档
完成标志：能在控制台看到每次调用的 token 数和成本，并回答"昨天哪个功能最烧钱"。
