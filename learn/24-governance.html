AI 内容治理：可运营、可申诉、可审计

审核的价值不在"拦住了多少"，而在"误判了怎么补救"。

0/6 步 · 0%
学完你能

能设计一套分层的内容治理流程：输入过滤、输出校验、人机协同、申诉闭环、审计留痕。

前置知识
  • 学过第十一课，理解安全边界
  • 学过第九课，会做评测和指标
  • 有真实用户内容（评论、工单、提问、上传文档）
本课 6 个学习目标
  1. 区分三类内容风险，并为每类配上不同强度的处置
  2. 设计分层输入审核，兼顾成本与覆盖率
  3. 做输出侧的事实校验、合规校验、品牌校验
  4. 设计人机协同流程与申诉闭环，把误判成本降到可接受
  5. 建立可审计的留痕机制，能回答"为什么这条被拦了"
  6. 用指标驱动治理迭代，而不是靠"感觉漏了"
第 1 / 6 步

三类风险，三种处置强度

风险类型例子处置强度误判代价
违法/严重违规暴恐、儿童色情、诈骗教程硬拦 + 上报低（几乎不该误判）
有害但不违法辱骂、歧视、医疗建议越界软拦 + 提示 + 转人工中
事实错误 / 幻觉编造的条款、错误的数字标注 + 引用 + 拒答高（最常见）
品牌与法律承诺收益、绝对化用语、侵权内容改写 + 审核高
隐私泄露复述他人手机号、病历脱敏 + 拦截高
!词表方案为什么必然失效

① 同音/变形/拼音/表情——"傻X"能写成十种形式；② 语境依赖——"怎么杀死进程"在技术文档里完全正常；③ 新词不断出现——你永远慢一步；④ 误杀严重——医疗、法律、安全行业的正常内容会被大面积拦掉。词表只能做第一道粗筛，真正的判定要靠模型 + 人工。

更重要的是：治理的目标不是"零漏放"，而是"漏放和误杀的加权成本最小"。这两个成本不对称——漏放一条违法内容可能带来监管风险，误杀一条正常提问只是让用户不满。所以策略上应该"高风险类别宁可误杀，低风险类别宁可放过"。

前端经验类比
和表单校验对照

你不会用一个正则校验所有字段——邮箱、手机号、金额各有各的规则。内容治理也一样：不同风险类别用不同手段（词表、分类模型、规则、人工），而不是一个万能过滤器。一个过滤器管所有事，结果就是什么都管不好。

申诉闭环

补全内容被拦后的申诉闭环。

用户内容被拦 │ ├─► 告知原因：必须是的，不能只说"违反规定" │ ├─► 提供入口（一键，不用找客服） │ ▼ 人工复核 ├─ 误判 → 放行 + 把样本加入，防止再犯 ├─ 正确 → 维持 + 给出更详细的解释 └─ 边界 → 放行但加 │ ▼ 结果通知用户 两个关键指标： - 率 = 申诉数 / 被拦数（太低说明通道有问题） - 率 = 申诉成立数 / 申诉数（衡量误杀严重程度）

阶段项目

项目一 · 知识库问答系统：内容治理

这一课给项目加上完整的内容治理能力：输入分层审核、输出三重校验、申诉闭环、审计留痕、周报指标。

这一课要做的
  1. 实现输入四层漏斗：规则 → 词表（带全角/空白归一化）→ 小模型分类 → 大模型判定
  2. 给审核 prompt 加结构隔离，测一次"忽略审核规则"的注入是否被挡住
  3. 上传文件入库前做审核，验证违规内容不会进知识库被 RAG 复述
  4. 实现输出三重校验：引用校验（拆断言比对材料）、合规校验（词 + 句式）、PII 检测
  5. 实现分级处置：放行 / 软改写 / 加提示 / 降级为"未找到" / 拦截
  6. 实现申诉闭环：一键申诉 → 人工队列 → 误判样本自动进评测集
  7. 建 moderation_records 表，实现"某用户完整审核历史"和"各层准确率"两个查询
  8. 做一张周报：拦截率、误杀率、申诉率、申诉成功率、人工复核占比
完成标志：注入测试被挡住；回答里编造的内容被引用校验拦下并改成"资料中没有相关说明"；用户申诉后 4 小时内收到结果；周报能显示"误杀率 4.2%，主要是 lexicon 层贡献"这样的可执行结论。
