第 1 / 8 步

为什么内存 Map 在生产环境一定不可行

第一课用 new Map() 存笔记，第二课换成了 SQLite。为什么要换？不是因为"生产要用数据库"这种教条，而是四个具体的技术限制。

限制具体表现什么时候暴露
重启即丢进程退出、容器重建、机器重启，数据全没第一次部署更新时
无法多进程共享开两个实例做负载均衡，A 写的 B 看不见第一次水平扩容时
无法按条件查询要"查这个用户最近 20 条"，只能全表遍历数据超过几千条时
没有事务扣款和记账两个操作，中途崩溃就数据不一致第一次涉及金额或库存时
!一个常见误区

"我的服务只有一个实例，所以内存够用" —— 这句话在重启面前立刻失效。哪怕是个内部工具，每次发版数据清零也是不可接受的。内存存储只适合缓存和测试替身，不适合当主存储。

这一课用 SQLite 举例，因为它是零配置的单文件数据库，node:sqlite 是 Node 22 内置的，不用装任何东西。但下面讲的建模、索引、分页、事务，在 PostgreSQL / MySQL 上完全一样——这些是关系数据库的通用知识，不是某个产品的特性。

tsNode 22 内置的 SQLite，不用装包
import { DatabaseSync } from 'node:sqlite'

const db = new DatabaseSync('./data.db')
db.exec('PRAGMA journal_mode = WAL')   // 允许读写并发，强烈建议
db.exec('PRAGMA foreign_keys = ON')    // 外键约束默认是关的！

const row = db.prepare('SELECT * FROM notes WHERE id = ?').get('abc')
const rows = db.prepare('SELECT * FROM notes WHERE user_id = ?').all('u1')

PRAGMA foreign_keys 默认关闭是 SQLite 的历史包袱。不打开它，你写的外键只是注释。
