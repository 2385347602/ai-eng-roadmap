Workflow 编排：把不确定的模型装进确定的骨架

五种编排模式，选错一种就会写出"能跑但不能维护"的流水线。

0/6 步 · 0%
学完你能

能为一个多步骤 AI 任务画出正确的编排结构，并处理重试、补偿、人工介入、可观测。

前置知识
  • 学过第八课，知道 Agent 和 Workflow 的区别
  • 学过第十二课，理解幂等和任务状态机
  • 手上有至少一个"三步以上"的 AI 流程
本课 6 个学习目标
  1. 识别五种基本编排模式，并知道各自适合什么任务形态
  2. 在状态机和 DAG 之间做出正确选择
  3. 设计幂等的步骤，让重跑和重放是安全的
  4. 在流程里正确放置人机协作节点
  5. 用补偿事务处理"中间步骤失败但前面已经产生了副作用"
  6. 把每个步骤变成可观测的 span，定位问题不用猜
第 1 / 6 步

五种模式，覆盖 90% 的场景

编排模式不多，但选错了会很难受。先认全五种：

① 链式（Prompt Chaining）
输入 → [步骤1] → [步骤2] → [步骤3] → 输出
        每步的输出是下一步的输入

适合：任务能明确拆成有序子任务
例子：提取要点 → 翻译 → 润色
优点：每步可单独测试、可缓存
缺点：一步错，后面全错（要加校验）
② 路由（Routing）
              ┌─► [简单问题 → 小模型]
输入 → [分类器] ┼─► [复杂问题 → 大模型]
              └─► [闲聊 → 固定回复]

适合：输入类型差异大，用一套处理必然浪费
例子：工单分类、模型分级路由
优点：成本能砍一半以上
缺点：分类错了，后面全错（分类要单独评测）
③ 并行（Parallelization）
        ┌─► [检查合规性] ─┐
输入 ───┼─► [检查准确性] ─┼─► [汇总]
        └─► [检查语气]   ─┘

两种用法：
- 分段：同一任务拆成独立子任务并行（总结 10 个文档）
- 投票：同一任务跑多次取共识（判断是否有害）

优点：延迟 = 最慢的那一路，不是总和
缺点：成本线性增长
④ 编排者-工作者（Orchestrator-Workers）
输入 → [编排者：拆解任务]
              │
              ├─► [工作者 A] ─┐
              ├─► [工作者 B] ─┼─► [编排者：汇总]
              └─► [工作者 C] ─┘

适合：子任务数量和内容取决于输入
例子：把一份需求拆成 N 个模块，每个模块单独实现
优点：能处理"事先不知道要拆几步"的任务
缺点：编排者的拆解质量决定上限
⑤ 评估者-优化者（Evaluator-Optimizer）
输入 → [生成] → [评估] ─┐
         ▲            │
         └── 不通过 ──┘
                      │
                      └─► 通过 → 输出

适合：有明确判定标准，且"一次写不好"
例子：代码生成 + 测试、文案生成 + 品牌规范检查
优点：质量显著提升
缺点：必须能判定"通过"，否则永远循环（要有次数上限）
模式一句话判断典型误用
链式步骤固定且有序把该并行的做成串行，延迟翻倍
路由输入类型差异大分类器没评测，路由错得莫名其妙
并行子任务互不依赖有副作用的步骤并行，造成重复写入
编排者-工作者拆几步取决于输入子任务简单固定，白花编排成本
评估者-优化者有客观判定标准没有明确标准，循环到次数上限
★组合比单选更常见

真实系统通常是"路由 + 链式 + 局部并行"。比如：先路由判断类型（路由）→ 按类型走固定步骤（链式）→ 其中"事实核查"和"合规检查"并行（并行）→ 最后评估是否通过（评估者-优化者）。先画清骨架，再往节点里填模型。

阶段项目

项目一 · 知识库问答系统：编排层

这一课把项目的问答链路从"一串 await"改造成可恢复、可观测、可人工介入的流程，并支持"批量处理"这种长任务。

这一课要做的
  1. 把问答链路改造成状态机：draft → classified → retrieving → answering → checking → done，每个转移落 runEvent
  2. 给"checking → answering"回边加计数器（最多 2 次），超了转 needs_human
  3. 实现 runStep 包装：stepKey = runId + 步骤名，纯计算步骤可 replay，有副作用的不可 replay
  4. 把"批量索引文档"改造成 DAG：先拓扑排序，无依赖的文档并行处理，失败的单独重试
  5. 加人工审批节点：涉及"发送给外部用户"的回答必须人工确认，展示完整正文，支持编辑后回写
  6. 给"建工单 → 扣额度 → 发通知"这条链路实现逆序补偿
  7. 每个步骤打 span，做一张流程看板：完成率、平均步数、重试率、人工介入率、各步 P95
完成标志：一条流程跑到第 3 步失败，重跑时前两步直接 replay 不重复执行；批量索引 100 份文档，中途杀掉进程重启，能从断点继续而不是从头开始；看板上能看到"重试率从 2% 涨到 15%"并定位到是哪个下游变慢。
