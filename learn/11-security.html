第 1 / 7 步

威胁模型：多出来的三条路

传统 Web 的信任边界很清楚：用户输入不可信，经过校验和转义后进入系统。 LLM 应用多了一条更麻烦的路——不可信的文本会变成指令。

三条新增攻击面
传统攻击面                      LLM 新增攻击面
─────────────                   ─────────────────────────────
① 参数注入 → SQL/命令            ③ 提示注入：文本变指令
② 越权 → IDOR                   ④ 工具滥用：模型替你执行
③ XSS → 输出转义                 ⑤ 数据外泄：模型把 A 的数据说给 B

共同点：攻击者不需要碰你的服务器，
        只需要让"某段文本"进入模型的上下文。
攻击入口后果防御在哪一层
直接提示注入用户自己输入绕过限制、套出系统提示输入隔离 + 输出校验 + 权限
间接提示注入PDF / 网页 / 邮件 / 代码注释在"正常使用"时被劫持内容来源标记 + 工具最小权限
IDOR 越权参数里带 id读到别人的数据数据层鉴权（不是应用层 filter）
RAG 越权召回检索未过滤权限答案里出现他人隐私权限进 SQL 的 where
Agent 工具滥用模型被诱导调危险工具删数据、发邮件、花钱工具白名单 + HITL + 最小权限
SSRF"帮我总结这个链接"打内网、读云元数据出站白名单 + 地址校验
输出型 XSS模型生成 <img onerror>在用户浏览器执行渲染时转义 / 禁用原始 HTML
PII 泄露日志、trace、缓存合规事故脱敏 + 最小化 + 留存策略
×最重要的一条认知

模型的输出是不可信输入。 很多人对"用户输入"很警惕，但对"模型输出"完全信任——直接 v-html、直接拼 SQL、直接 eval、直接当文件路径。模型输出和用户输入同级，甚至更危险，因为它看起来很像"系统自己说的话"。

前端经验类比
和 Vue 的 XSS 防护对照

Vue 默认对插值做转义，只有你显式用 v-html 才危险。LLM 应用里，"模型输出"就是那个默认需要转义的东西。每一处把模型输出当代码/HTML/SQL/路径用的地方，都是一个 v-html。

阶段项目

项目一 · 知识库问答系统：安全加固

这一课把项目从"能跑"推进到"敢给别人用"。产出物是一份威胁模型 + 每一层的具体防御代码 + 一组能验证防御有效的攻击用例。

这一课要做的
  1. 写一份威胁模型：列出所有入口（用户输入、上传文档、URL 抓取、MCP 工具）、所有出口（回答、引用、日志、trace）、每条路径的后果和防御
  2. 身份改造：删掉所有请求体里的 userId / tenantId，改成从会话解出；写一个 lint 规则禁止再出现
  3. 检索与查询全部加权限条件，用两个不同权限的账号做越权测试（预期：互相看不到）
  4. 缓存 key 加 userId + permVersion，验证 A 问过的问题 B 拿不到 A 的答案
  5. 实现 assertSafeUrl：协议白名单 + 私有地址拒绝 + DNS 复查 + 重定向复查，用 10 个恶意 URL 测试
  6. 输出渲染改造：Markdown 禁用原始 HTML，HTML 走 DOMPurify 白名单，链接限制协议 + noopener
  7. 入库前 PII 分级：高风险（身份证/银行卡）不存原文只存哈希，其余脱敏
  8. 构造 5 个注入用例（PDF 藏指令、对话历史伪造、base64 编码指令），验证即使注入成功也调不动危险工具
完成标志：能拿出"攻击用例全部被挡"的记录；用低权限账号手动尝试读别人的文档、猜别人的订单号，都拿不到数据；上传一份藏了指令的 PDF，系统只把它当文本总结，不会去执行任何动作。
